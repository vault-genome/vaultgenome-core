# The acceptance trial of October 2026 — every kit on the released code, in order

**What this is.** After v0.6.0 (2026-10-17) the tree's hardware kits are
run again, one at a time, from `main` at the commit each row names, and
every run's record is committed under the kit's `evidence/` as always. A
trial passes when its run reaches the criterion its claim states in
[`VERIFIABLE-CLAIMS.md`](../VERIFIABLE-CLAIMS.md); a kit that no longer
runs on the current code is fixed in a pull request of its own, and the
trial is run again. Nothing here is a new claim: it is the existing
claims checked against the code that is released now, on the hardware
that is available now.

**Why.** Most drills and door measurements were last run on 2026-10-15,
before the Return Path wire became 1.1 (0.5.0) and the audit schema v7
(0.6.0). The claims describe those runs truthfully; whether the released
code still produces them is the question this trial answers, and the
answer is what a buyer in any sector asks first.

**How it is run.** In the order below (the cheap CPU-only kits first,
the drills next, the GPU kits last). Kits that share nothing — each
boots its own guests under its own stamp, with its own bucket and
firewall rules — run in parallel; a kit that measures the host (the
soaks, the parallel sessions) runs with no other CPU kit in its cloud. Each row records the run's stamp,
the commit the binaries were built from (`versions.txt` in the evidence),
the outcome against the criterion, and any deviation. A failure is not
edited away: the row says what failed, the fix is a pull request, and a
new row says what the second run did.
